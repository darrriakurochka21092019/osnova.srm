# Архитектура 0.1

Модульный монолит. React + TypeScript + Vite обслуживается Fastify. Socket.IO передаёт события комнат; серверные операции записываются до ответа клиенту. Excalidraw — редактор; PDF.js — рендеринг страниц; pdf-lib — проверка PDF и экспорт.

## Владение данными

Первый аккаунт — единственный преподаватель-владелец. Ученик создаётся преподавателем и активирует вход через одноразовое приглашение. Гость по личной ссылке ученика имеет доступ к его учебным комнатам и доскам; данные кабинета, домашние задания и финансы остаются за авторизацией ученика. Прежние разовые гости имеют доступ только к выданной доске. Проверки идут на сервере для HTTP, файлов и подключения к комнате.

Постоянные сущности: users, sessions, students, boards, board_members, pages, operations, snapshots, invites, files, records, audit_events, classrooms, classroom_members, classroom_guests, lesson_sessions, lesson_attendance, lesson_messages. UUID используются независимо от имени, телефона или почты. `records` хранит типизированные Zod-схемами учебные и организационные записи с owner_id и student_id. Финансовые начисления выводятся из проведённых занятий, а не дублируются второй таблицей балансов.

Данные прежней CRM не мигрировались. Перед интеграцией нужен аудит её авторизации, таблиц, API и идентификаторов; API этой версии не является готовым SSO-адаптером.

## Урок как основной сценарий

`classrooms` — постоянная комната, связанная с одной канонической доской. Уникальный `(owner_id, member_key)` задаёт индивидуальную комнату по UUID ученика или мини-группу по отсортированному набору UUID. Создание ученика и комнаты выполняется в одной транзакции; для прежних учеников комнаты достраиваются при чтении списка. Подготовка доски не начинает урок и не создаёт финансовое начисление. Старые доски и файлы остаются материалами; безопасная незанятая доска ученика может стать основной, а пустая ещё не использованная комната может принять явно подготовленную прежнюю доску.

Личная ссылка `/learn/:id#secret` постоянна до отзыва/обновления. Fragment не входит в HTTP URL. В отличие от разовых приглашений, секрет повторно доступен владельцу из БД для копирования; база и резервные копии поэтому содержат действующие личные ссылки. Владелец может отозвать ссылку со всеми выданными через неё гостевыми сессиями. Гостевая cookie действует 12 часов, затем по той же личной ссылке можно войти снова. При паузе ученика доступ закрывается. Одна личная ссылка также находит активное или ближайшее занятие мини-группы; общая анонимная ссылка группы не выдаётся.

Маршруты интерфейса: `/lessons` — комнаты в кабинете; `/lesson/:id` — вход/ожидание; `/lesson/:id/prepare` — подготовка; `/lesson/:id/live/:sessionId` — занятие; `/lesson/:id/summary/:sessionId` — итоги в кабинете; `/lesson/:id/materials/:sessionId` — сохранённый холст. Вход из расписания передаёт конкретный lessonId. Один преподаватель начинает только одно занятие одновременно. Преподаватель переводит planned/rescheduled → live → completed; ученик не может начать/завершить занятие. Операции начала/конца идемпотентны. При входе вне расписания создаётся запись урока с нулевой ценой, которую можно уточнить позже.

`lesson_sessions` хранит фактическое время, общие итоги, приватную заметку и UUID назначенных заданий. Приватная заметка исключается из всех ответов участникам, кроме владельца. При повторном сохранении итога одно задание не назначается второй раз каждому ученику. Начало и завершение фиксируют неизменяемые снимки сцены и фона. Просмотр прошлого занятия и локальное перелистывание его PDF не меняют текущую доску.

Комментарии сохраняются с UUID клиента и безопасным повтором запроса. Участники, стадия входа, поднятая рука и переходы начала/конца передаются через Socket.IO. Это реальные подключения; видеоокна — обозначенные заглушки без обращения к камере/микрофону. Общий холст использует прежний протокол сохранения. Полный кабинет не обновляется по таймеру внутри активного редактора.

## Сохранение доски

Клиент хранит подтверждённую версию каждого объекта и отдельные локальные изменения. Отправляется UUID операции и список изменённых элементов с baseVersion. В транзакции сервер блокирует страницу, проверяет доступ и базовые версии, сохраняет допустимые элементы и tombstones, увеличивает ревизию, пишет результат операции и снимок. Только после COMMIT операция рассылается и подтверждается.

Повтор operationId возвращает прежний результат. Разные объекты сливаются. Для одного объекта устаревший baseVersion вызывает конфликт с возвратом текущего объекта. Клиент сохраняет локальный конфликтный вариант в IndexedDB и предлагает переносимый экспорт. Побуквенного CRDT нет. Удаления не выводятся из отсутствия чужих объектов в переданной сцене.

После reconnect клиент входит в комнату и получает актуальную сцену. Неподтверждённые операции повторяются. Индикатор «Сохранено» зависит от ответа API. Локальный черновик и идентификатор неподтверждённой операции сохраняются в IndexedDB с ключом user_id + page_id. Чужие обновления добавляются без включения в локальную undo/redo-историю редактора.

Во время контакта пера/мыши живой штрих обрабатывает только Excalidraw. Клиент не копирует сцену, не пересчитывает принадлежность пометок и не записывает IndexedDB на каждом движении. После финализации native pointerup микрозадача фиксирует неизменяемую копию только изменённых объектов. Это не позволяет отложенной работе от предыдущего штриха вмешаться в следующий быстрый контакт. Исходное состояние перемещения PDF использует уже зафиксированные объекты без копирования всех прежних точек. События курсора ограничены 20 в секунду и не буферизуются при потере связи. Чужие изменения и обработка HTTP-подтверждений ждут завершения активного жеста; обычное подтверждение сохранения не вызывает повторную установку сцены.

Локальные контрольные точки объединяются с задержкой 120 мс, отправка серверу — 400 мс; работа откладывается, пока идёт жест. IndexedDB версии 2 разделяет данные сцены и неизменяемые бинарные файлы изображений: контрольные точки содержат идентификаторы файлов, бинарные данные сохраняются только при отсутствии в кэше. Прежние черновики версии 1 с вложенными файлами читаются и переносятся без потери локальных правок. Неиспользуемые файлы очищаются при повторном открытии/выходе с доски только при отсутствии неподтверждённого черновика. Проверка наличия и запись файлов выполняются в одной транзакции, поэтому очистка не оставляет новый черновик без изображений.

Снимки: последние 50 обычных на страницу плюс контрольные версии уроков. История показывает до 150 последних версий, включая контрольные; сами контрольные версии не удаляются этой ротацией. Журнал идемпотентности в этой версии не ротируется. Перед внедрением ротации нужно согласовать окно офлайн-повтора.

## Файлы и PDF

Файл проверяется по сигнатуре, MIME, размеру; PDF разбирается для проверки числа страниц, изображения — для проверки размеров. SVG, HTML и архивы не разрешены. Имена хранения — случайные ключи, файлы лежат вне web-root. Выдача требует сессии и доступа к доске/учебной записи. Проверка подлинности содержимого не заменяет антивирусную инфраструктуру крупной школы.

Оригинал PDF сохраняется на сервере. Производные PNG собраны в `customData.presentation.slides` одного перемещаемого image-объекта общего холста. `slideIndex` и `fileId` задают активный слайд и синхронизируются обычными элементными операциями. Аннотации имеют `customData.slideAnnotation = {presentationId, slideIndex}`. Неактивные пометки скрываются только проекцией при рендеринге: в сохранённой сцене они не становятся удалёнными. При перемещении/изменении размера презентации связанные пометки преобразуются вместе с ней. При импорте PDF с разными форматами страниц слайды вписываются без растяжения в общую рамку. Остальные картинки слайдов подгружаются при переключении или экспорте сцены. Шрифты, CMaps, WASM и worker размещаются локально.

## Единый холст и фон

`boards.canvas_page_id` указывает на одну каноническую сцену. Протокол страниц остаётся внутренним форматом хранения; системы страниц в интерфейсе нет. `POST /boards/:id/canvas` идемпотентно объединяет старые материалы: обычные страницы раскладываются рядом, страницы одного PDF объединяются в презентацию с отдельными пометками. Исходные дополнительные страницы и их история не удаляются; первая версия сохраняется снимком. Первое преобразование выполняется владельцем при открытии доски. Старые клиенты не могут продолжать писать в дополнительные сцены после объединения.

Фон `boards.background`: white/grid/ruled/dots. Значение проверяется сервером, сохраняется и передаётся участникам событием `board-background`. Экранный рисунок привязан к координатам и масштабу холста; PNG/PDF-экспорт рисует такой же фон под объектами. Смена фона не создаёт тысячи элементов сцены.

Проекция скрытых слайдов и поиск родителей пометок используют индексы по id, а не повторный обход всей сцены для каждой пометки. Если редактор нормализует старые индексы объектов скрытого слайда, сохраняется новая нормализованная версия; отменяется только виртуальное удаление. Это предотвращает цикл бесконечной нормализации и повторных обновлений React.

## Локальный и серверный режим

Без DATABASE_URL используется дисковая PGlite. Это осознанный адаптер для простого запуска на Windows; один процесс API на папку данных. В Docker используется PostgreSQL 17. Оба режима выполняют один SQL-контракт и миграцию без удаления существующих данных. Между форматами нет автоматического переноса базы: перенос нужно делать отдельно с проверкой.

Видео в эту версию не входит и не блокирует ни доску, ни сохранение. Подключение LiveKit/Jitsi проектируется отдельным модулем после испытаний сети.

## Предметные инструменты доски

`board/catalog.ts` содержит каталоги фигур, линий, цветов стикеров, шрифтов и формул. `board/geometry.ts` строит обычные Excalidraw-примитивы. Объёмные тела — редактируемые векторные проекции, сгруппированные по customData.boardFigure с исходной геометрией. Выбор фигуры включает custom-инструмент: pointer capture рисует лёгкое SVG-превью, а pointerup вставляет одну нативную группу в пределах жеста и одну undo-операцию. Числовых параметров в интерфейсе нет. Растягивание/поворот используют native-маркеры, рёбра доступны после разгруппировки. Превью не пишет сцену/черновик; Esc/pointercancel/blur снимают захват. Новых библиотек и платных API не добавлено.

Ручка и маркер хранят независимые цвет/толщину в текущем редакторе. Палитра принимает RGB/HEX; толщина 0,5–40 с шагом 0,5. Текст использует локальные Helvetica/Excalifont/Nunito/Cascadia/Virgil и стандартные размеры. Смена шрифта/размера пересчитывает геометрию текста; подпись стикера остаётся bound text. Готовые формулы вставляются обычным редактируемым текстом с Unicode-символами и индексами, а не изображением/HTML. Синтаксиса LaTeX в этом редакторе формул нет.

Подчёркивания создаются жестом native-инструмента line. После завершения pointerup один раз разворачивается двойная/волнистая/штрихпунктирная линия или морфемный знак в native-векторы; на каждом движении пера вычисления не выполняются. Составные линии сгруппированы и редактируются обычными handles. Нормализация не затрагивает рёбра программно добавленных фигур.

Цветной стикер — rectangle со свойством customData.sticker и привязанным текстом. Рукописная пометка внутри получает customData.stickerAnnotation = {stickerId}; captureCanvas перемещает/масштабирует/вращает её вместе с листочком. Стикер внутри PDF сохраняет принадлежность слайду, а его пометки наследуют видимость через стикер. Преобразования выполняются в порядке PDF → стикер → его пометки, чтобы не применять смещение дважды.

Замок использует native locked на объекте и его bound text. Это защита от случайного редактирования; права edit/view по-прежнему проверяются сервером. `board/interaction.ts` на обычном клике выделения проверяет видимую геометрию с учётом поворота и порядка слоёв, выбирает locked-объект вместе с группой и bound text и блокирует drag до открепления. Замочек появляется у любого выделения, отдельный список не требуется. Проверка не выполняется на движениях пера. Зажатая ПКМ захватывает указатель и меняет только scrollX/Y с учётом zoom; сцена и undo не изменяются, контекстное меню не открывается. Нижняя панель урока имеет однотонный фон и не имитирует разметку холста.

Контекстные настройки вычисляются только при завершённом жесте. Ввода по точкам, записей IndexedDB и полного анализа выделения во время прижатого пера нет. Слайды переключаются только в панели у выбранного PDF. На сохранённом холсте перелистывание локальное и не записывает активный slideIndex рабочей доски. Глобальные миниатюры и верхний переключатель удалены. Пункт исходных файлов убран из меню доски; внутреннее хранение оригинала PDF и проверка доступа к файлам сохранены для импорта и истории.
