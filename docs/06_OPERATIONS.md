# Запуск, обновление, резервные копии

## Windows: локальная работа

1. Установите Node.js 24 LTS с официального сайта nodejs.org и Git с git-scm.com. Перезапустите PowerShell. Проверьте `node --version`, `npm --version`, `git --version`.
2. Выполните команды из README. `npm ci` установит зафиксированные версии и скопирует шрифты и ресурсы PDF в public. Интернет нужен для установки, но платные API для работы не нужны.
3. Сохраните пароль преподавателя. Свободной регистрации учеников нет: создайте ученика и один раз передайте его постоянную ссылку на занятия. Приглашение для активации личного кабинета — отдельная необязательная настройка.
4. У API порт 3001, у разработки — 5173. Обе службы запускает `npm run dev`. Для остановки нажмите Ctrl+C в PowerShell.

Вместо удаления базы для исправления ошибки сначала сохраните копию папки данных. Если занят порт, закройте предыдущий экземпляр. Ошибка «DATA_DIR занят» означает, что эта база уже открыта другим процессом. Не запускайте backup или второй API одновременно с локальной PGlite.

## Обновление локальной версии

Остановите приложение (Ctrl+C), оставаясь в прежней папке проекта:

```powershell
npm run backup
git pull --ff-only
npm ci
npm run dev
```

Откройте http://localhost:5173 и обновите страницу. Если доска показывает «Некорректные координаты», после установки исправления откройте ту же доску в том же браузере и по тому же адресу (localhost и 127.0.0.1 имеют разные хранилища). Не очищайте данные сайта: исправленная версия использует локальный черновик для восстановления штрихов и очереди отправки. Не заменяйте `data/` и `.env`: миграция добавляет таблицы комнат и занятий к существующей базе. Если Git сообщает о локальных изменениях, сохраните их отдельно и разберите конфликт; не выполняйте reset с удалением изменений. Личные ссылки содержат секрет: передавайте их нужному ученику, не публикуйте их и резервные копии. Ссылки работают извне только при доступном сервере и корректном APP_ORIGIN.

## Перенос локальной версии на другой компьютер

1. Остановите приложение и выполните `npm run backup`.
2. Перенесите исходники репозитория и папку резервной копии. Папка node_modules не нужна: на другом компьютере выполните `npm ci`.
3. Восстановите в новую папку:

```powershell
npm run restore -- "C:\OSNOVA\backup-copy" "C:\OSNOVA\data-restored"
```

4. В `.env` укажите `DATA_DIR=C:/OSNOVA/data-restored`. Запустите приложение и откройте прежнюю доску, файл и задание. Восстановление не перезаписывает непустую папку и проверяет SHA-256 базы и всех файлов.

Копии содержат учебные данные и сеансы. Храните их в защищённом месте, отдельно от компьютера с приложением; не публикуйте в GitHub. После восстановления на другом компьютере завершите лишние сеансы в настройках.

## Сервер в РФ: Docker Compose и HTTPS

Нужны Linux VPS, Docker с Compose, домен и DNS A-запись на IP сервера. Из сетей учеников нужно отдельно проверить доступность выбранного VPS. Сам код не приобретает домен или сервер.

Клонируйте репозиторий на сервер, создайте `.env` на основе `.env.example` и добавьте:

```dotenv
DOMAIN=lessons.example.ru
POSTGRES_PASSWORD=<длинный_случайный_секрет_из_букв_и_цифр>
SETUP_TOKEN=<другой_длинный_случайный_секрет>
```

Имя домена замените своим. Пароль БД задавайте буквами/цифрами без URI-разделителей, либо корректно URI-кодируйте его в DATABASE_URL. Для генерации используйте менеджер паролей или `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail 100 app
```

Откройте `https://<ваш-домен>`. При первоначальной настройке понадобится SETUP_TOKEN. Публичная первоначальная настройка без этого ключа в production запрещена кодом. Caddy получает TLS-сертификат; должны быть доступны 80/443. Приложение и БД наружу не публикуются. Контейнер приложения работает непривилегированным пользователем.

Для обновления:

```sh
git pull --ff-only
docker compose up -d --build
```

Перед обновлением сохраните копии БД и файлов. Именованные volumes переживают пересборку. Не выполняйте `docker compose down -v`: этот флаг удаляет данные.

## Резервирование PostgreSQL и файлов

Минимум ежедневно; копию переносите вне VPS. На время согласованной копии остановите приложение, оставив БД запущенной:

```sh
mkdir -p backups/manual
docker compose stop app
docker compose exec -T db pg_dump -U osnova -d osnova -Fc -f /tmp/osnova.dump
docker compose cp db:/tmp/osnova.dump backups/manual/database.dump
docker compose cp app:/app/data/files backups/manual/files
docker compose start app
```

Проверьте наличие дампа и файлов; зафиксируйте время и версию приложения. `docker compose cp` работает и для остановленного контейнера. После проверки перенесите копию на другой носитель. Для автоматизации используйте cron/systemd на сервере и оповещение об ошибке; задача резервирования этим репозиторием автоматически не устанавливается.

Восстановление проверяйте на отдельном пустом окружении. Остановите app, скопируйте дамп в db, примените `pg_restore --clean --if-exists --no-owner -U osnova -d osnova /tmp/osnova.dump`, верните files в `/app/data/files` с владельцем node (uid 1000), запустите app. Не восстанавливайте непроверенный дамп поверх единственной рабочей БД. Скрипт `restore.ts` предназначен для локального PGlite-формата; он не читает pg_dump.

## Перед реальными уроками

Проверьте полный сценарий учитель + ученик с независимых устройств, доступность из сетей РФ, PDF со сканами/кириллицей, 60–90 минут работы, отключение Wi-Fi и отзыв ссылки. Проведите восстановление резервной копии на чистом окружении. Согласия и организационные документы оператора персональных данных оформляются отдельно: код не подтверждает соблюдение всех правовых требований.

## Доступность и ограничения

Все пользовательские даты — Europe/Moscow (UTC+3). При выключенном API напоминания не создаются; просроченные задания обрабатываются при следующем проходе планировщика. Локальный запуск доступен этому компьютеру; localhost в ссылке не откроет урок у ученика дома. В production APP_ORIGIN должен точно совпадать с HTTPS-адресом.

### Обновление панелей доски 29 октября

Зависимости и схема БД не изменены. Остановите dev-сервер Ctrl+C, из папки проекта выполните `npm run backup`, `git pull --ff-only`, `npm run dev`, затем Ctrl+F5 в браузере. Установку node_modules повторять для этого обновления не требуется. Сохранённые доски и старые стикеры остаются; из галереи удалены только прежние декоративные варианты. В production нужно заново выполнить build; новые /board-fonts и /board-stickers копируются Vite из public автоматически. При откате данные новых текстов остаются в image/customData и приватных файлах, хотя старый UI не умеет форматировать их.

### Компактные свойства и прямой ввод 30 октября

Схема базы и зависимости не изменены. Из рабочей папки проекта после Ctrl+C: `npm run backup`, `git pull --ff-only`, `npm run dev`; в браузере Ctrl+F5. Повторный `npm ci` для этого обновления не нужен. Проверьте: T → клик → ввод; один клик по фигуре открывает свойства, перенос не меняет её форму; маркеры меняют размер; отдельный замок закрепляет и открепляет. Старые объекты и файлы сохраняются. Для production пересоберите приложение обычным порядком.
